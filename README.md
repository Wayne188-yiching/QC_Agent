# QC Agent

遊戲美術品管工具。讀原始檔、量測、產出可拖時間軸的報告。

**設計前提：檔案直接進瀏覽器，不經過截圖或錄影。** 拿錄影檔 QC 動態，
等於用照片檢查建築物有沒有水平。所以這個工具讀的是資料層——骨骼、
關鍵影格、緩動曲線、圖集座標、像素 alpha——不是畫面。

一切在本機執行，素材零上傳。

---

## 用法

```bash
python qc.py <skeleton檔>                        # 主控台報告
python qc.py <skeleton檔> --html 報告.html        # 加產出可互動報告
python qc.py <skeleton檔> --accept <rule>         # 把某條判定標記為刻意
```

需求：Python 3、`pip install Pillow`（沒有的話像素層檢查會降級為推測，其餘照跑）。

`--html` 產出的是**單檔自足**的 HTML，雙擊就開，不用伺服器。

### 報告怎麼看

- **逐格** — 拖時間軸、空白鍵播放、左右鍵單格
- **首尾疊圖** — 青色是第一格、洋紅是最後一格，紅虛線標出差距。**判斷循環接不接得起來就看這個**
- **軌跡** — 全影格疊影，看運動路徑

右側問題清單點下去會跳到對應時間點並標出被點名的骨骼。

## 判準四層

| 層 | 來源 | 意思 |
|---|---|---|
| **L1** 客觀錯誤 | 通用原則 | 任何風格下都是錯 |
| **L2** 規範違反 | 公司規範文件 | 違反白紙黑字（**尚未實作**，等規範文件） |
| **L3** 風格偏離 | 認可成品反推 | 不一定錯，但不像你們家的東西 |
| **L4** 市場對照 | 競品標杆 | 純情報（**尚未實作**） |

### 基準檔

偵測正確不等於判斷正確。`--accept <rule>` 會在**資產目錄**寫出
`qc-baseline.json`，之後該判定降為「參考」，並**保留原始判定文字**——
讓後面接手的人知道當初量到什麼、為什麼被接受。

## 中介格式

網頁端只認識這個形狀。Spine 只是第一個生產者，**任何引擎只要能吐出它，
就能驅動同一個檢視器，檢視器一行都不用改。**

```jsonc
{
  "duration": 1.0,          // 秒
  "frames": 31,
  "fps": 30,
  "ref": 1604.8,            // 角色可見高度，所有位移都換算成它的百分比
  "bones": [
    { "name": "2_tail", "parent": "2_body",
      "f": [[x, y, angleDeg, length], ...] }   // 世界座標，每格一筆
  ],
  "slotBone": { "slotName": "boneName" },
  "vis":      { "slotName": [0, 1, 1, ...] }   // 每格可見與否
}
```

`ref` 是關鍵：**引擎單位對美術沒有意義**。所有數值都換算成
「佔角色可見高度的百分比」「該部件自身長度的幾倍」
「它平常每格移動量的幾倍」才回報。

## 檔案

| | |
|---|---|
| `qc.py` | 解析器 + 規則引擎 + 烘焙器 + 報告產生器 |
| `viewer.html` | 報告模板。`qc.py` 把資料注入 `/*__DATA__*/` 後輸出 |
| `shell.html` | 最初的視覺架構稿。已被 `viewer.html` 取代，留著當設計參考 |

`qc.py` 檔頭有完整的**校正紀錄** — 每一條規則為什麼改成現在這樣，
都是被真實資產打臉後改的。改規則前先讀那段。

## 支援範圍

- Spine **3.8** 舊式 atlas（`xy`/`size`/`orig`/`offset`，區塊縮排）
- Spine **4.x** 新式 atlas（`bounds`/`offsets`，區塊不縮排）
- **mesh** 與 **region** 兩種附件（多邊形打包 vs 矩形打包）
- JSON 骨架，含**副檔名寫 `.skel.bytes` 但內容其實是 JSON** 的情況
- 二進位 `.skel` **尚未支援解碼**
